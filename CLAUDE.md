## Project Overview

PUSE is a save editor for Pokemon Unbound (v2.1.1.1). It has two runtime modes:
- **Local mode** (`VITE_RUNTIME_MODE=local`): all parsing/editing runs in-browser (JS)
- **Backend mode** (`VITE_RUNTIME_MODE=backend`): uses FastAPI at `http://localhost:8000`

A Nintendo Switch homebrew port is in progress under `switch-homebrew/`.

## Commands

### Frontend (run from `frontend/`)

```bash
npm install
npm run dev          # dev server at http://localhost:5173
npm run build        # production build
npm run lint         # lint all files
npm run parity:all   # all regression scripts in frontend/scripts/
npm run icons:manifest  # regenerate icon manifests after changing pinned commits
```

### Backend (run from `backend/`)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### Docker (full stack)

```bash
docker compose up --build
```

### Switch homebrew (from `switch-homebrew/`)

```bash
switch-homebrew/scripts/build_docker.sh   # full Docker build + SD bundle
switch-homebrew/scripts/sync_romfs_data.sh  # sync backend/data -> romfs/data
```

There is no configured test runner (`package.json` has no test script). Regression scripts live in `frontend/scripts/` and are run via the `npm run parity:all` / individual npm scripts above.

## Architecture

### Dual runtime parity

`frontend/src/services/apiClient.js` is the key abstraction. It exports `createApiClient(runtimeMode)` which returns either:
- A **backend client** that calls FastAPI REST endpoints
- A **local client** that imports and calls JS modules in `frontend/src/core/`

The `frontend/src/core/` directory is a JS port of the backend Python logic with behavioral parity as the goal. Every core module has a backend counterpart:

| Frontend | Backend |
|---|---|
| `core/party.js` | `modules/party.py` |
| `core/pc.js` | `modules/pc.py` |
| `core/bag.js` | `modules/bag.py` |
| `core/money.js` | `modules/money.py` |
| `core/sections.js` | `core/sections.py` |
| `core/checksum.js` | (inline in backend modules) |
| `core/rtc.js` | `tools/rtc_*.py` |
| `core/saveConvert.js` | `tools/save_convert.py` |
| `core/gameProgress.js` | `modules/game_progress.py` |
| `core/rosterExport.js` | (backend uses same JS via apiClient roster build) |
| `core/pokedexFlags.js` | `modules/pokedex_flags.py` |
| `core/dexProgress.js` | (progress payload; TM ownership from `modules/bag.py`) |
| `core/statCalc.js` | (inline in party modules) |
| `core/levelCap.js` | (uses `unbound_level_caps.json`) |
| `core/unboundLearnset.js` | (static `species_learnsets.json`) |

**When behavior differs, backend is authoritative.** See `switch-homebrew/RULES.md` section 2.

### Backend save lifecycle

`backend/main.py` holds all save state in `current_save["data"]` (in-memory bytearray). Edits accumulate without writing to disk. `/save-all` commits: recalculates checksums for trainer section (id=1), bag sectors (13-16), PC buffer sectors, and absolute-touched sectors, then writes `edited_save.sav`. `/download` serves the file.

### Frontend state flow

`App.jsx` owns global state: loaded save, active tab (party / pc / all / bag / dex), selected Pokemon, PC box, export selection queue, legit mode, cap profile. Lazy-loaded components (`PartyGrid`, `PCGrid`, `AllPokemonTable`, `BagView`, `LivingDexPanel`, `PokemonEditorModal`, `AddPcPokemonModal`) receive `client` as a prop. Save/download calls go through `client.saveAll()` then `client.downloadSave()`. Roster copy/export uses `client.copyRosterMarkdown()`, `client.exportFullRoster()`, and selection variants.

The **All** tab (`AllPokemonTable`) aggregates every party + PC Pokemon via `client.getAllOwnedPokemon()` (backend + local parity: loops party then `ROSTER_EXPORT_BOX_IDS`, tagging each row with `_source` and `box`/`slot`). It is read-only display with sort/filter/multiselect; rows open `PokemonEditorModal`, and the shared export-selection queue powers in-table copy/export plus mass-release. PC Pokemon can be released (deleted) via `client.releasePc({ box, slot })` (`POST /pc/release` backend, `releasePcMon` in `core/pc.js` local), which zeroes the slot and recommits checksums on `saveAll`. Party deletion is intentionally unsupported (packed list requires slot-shifting).

### Static data

ROM-extracted lookup tables live in `backend/data/` and are mirrored into `frontend/src/core/` (JSON imports) and `switch-homebrew/romfs/data/` (via sync script). Never edit data files by hand — they are generated by tools in `backend/tools/`.

| Generator | Output | Frontend mirror |
|-----------|--------|-----------------|
| `bootstrap_species_types.py` | `species_types.json` | `frontend/src/core/species_types.json` (also via `sync_speed_tier_static_data.py`) |
| `sync_unbound_dex_learnsets.py` | `species_learnsets.json` | `frontend/src/core/species_learnsets.json` |
| `scripts/build_unbound_speed_tiers.py` | `unbound_speed_tiers.csv` + `unbound_speed_tiers.json` | `frontend/src/core/unbound_speed_tiers.json` |
| `bootstrap_species_evolution.py` | `species_evolution_meta.json` | `frontend/src/core/species_evolution_meta.json` |
| `build_species_constants.py` | `species_constants.json` (species id → pokeemerald `SPECIES_X` constant, parsed from `species_id.txt`) | `frontend/src/core/species_constants.json` |
| ROM extract scripts (base stats, abilities, etc.) | various `backend/data/*.json` | matching `frontend/src/core/*.json` |

`bootstrap_species_types.py` prefers ROM extraction (`extract_unbound_species_types.py`) when `Unbound.gba` is available; otherwise it falls back to Showdown pokedex types matched by species name.

**Speed tiers (expert mode):** Source of truth is `backend/local_artifacts/expert_bosses.xlsx` (trainers doc, gitignored) plus `backend/data/unbound_level_caps.json` (boss order/caps). Regenerate with `python scripts/build_unbound_speed_tiers.py` (requires `openpyxl`). Without the xlsx, run `python backend/tools/sync_speed_tier_static_data.py` to refresh JSON from the committed `unbound_speed_tiers.csv`.

**Strategy reverse indexes:** `python backend/tools/build_strategy_indexes.py` emits three Markdown lookup files into `backend/data/` for use as external strategy-assistant knowledge (not consumed by the app runtime, not mirrored to frontend):

| Output | Contents | Source data |
|--------|----------|-------------|
| `ability_species_index.md` | ability → species (hidden flagged `(H)`) | `species_abilities_meta.json` + `abilities.txt` + `pokemon.txt` |
| `type_species_index.md` | type → species (dual-types listed twice) | `species_types.json` + `pokemon.txt` |
| `move_species_index.md` | curated role-defining move → species | `species_learnsets.json` + `moves.txt` + `pokemon.txt` |

These reverse the per-species data so an LLM can answer "which species can have ability/type/move X" with a direct read instead of memory. The move index is a curated competitive set (weather, hazards, setup, recovery, priority, pivots, utility) defined by `CURATED_MOVES` in the script; generic coverage moves are excluded to keep the file small and useful as a discovery filter. Regenerate after any ROM data refresh.

### Switch homebrew

`switch-homebrew/` contains a Plutonium (libnx) C++ port, currently in development. Build requires Docker with devkitPro. The backend Python is the canonical behavior reference. See `switch-homebrew/RULES.md` and `switch-homebrew/PLAN.md` for full requirements.

## Key Conventions

### Feature phase handoff
When starting or closing work on a web feature, update [`docs/FEATURE_PHASE_HANDOFF.md`](docs/FEATURE_PHASE_HANDOFF.md) (phase index, session log, verification). Copy the phase template for new work.

### API contracts are stable
Payload keys (`nature_id`, `item_id`, `ability_index`, `current_ability_index`, etc.) are shared contracts between frontend and backend. Change both sides together or don't change at all.

### Checksum after every mutation
Any code path that writes save data must end with checksum recalculation. In backend: `bag_mod.gba_checksum` / `bag_mod.recalculate_checksum` / `party_mod.wu16`. In frontend local mode: `checksum.js`.

### Legit mode
`App.jsx` has a `legitMode` flag (persisted to localStorage). Components receive it as a prop. It enforces 510 EV cap and restricts some edits. Don't bypass it in new features.

### Personal save files
Keep `.sav`/`.srm`/ROM files under `backend/local_artifacts/` (gitignored). Never commit save files.

### Icon assets are optional
Neither backend nor frontend requires icons to run. Missing icons produce a placeholder. Icon manifests at `frontend/src/data/pokemon-icon-manifest.json` and `frontend/src/data/item-icon-manifest.json` are committed.
